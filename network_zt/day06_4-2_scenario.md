# A사 Zero Trust 적용 방안
## 5대 원칙 적용 방안
- ID: 모든 접속 경로에서 FA를 켜서 비밀번호만으로 로그인되지 않게 설정한다 
- Device: 등록된 기기에서만 로그인 가능하도록 설정한다 
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다
- Application: 정산 내역은 재무팀만 조회하도록 권한을 준다 
- Policy: 새벽이나 해외 접속, 20건 이상 조회는 점수를 주고 추가 인증을 하거나 차단으로 이어질 수 있도록 한다 


## 판단과 집행
- PDP(결정): 요청 정보를 받아 허용/추가확인/거부를 정하는 판단 서버 
- PEP(집행): 정산 포털 앞의 프록시/결정대로 통과/추가 인증/차단하고 로그를 남긴다 


## 흐름도
```
사용자 --요청--> PEP --문의--> PDP
                                |  1. 필수 조건 검사 (재직 중, 등록된 기기): 어긋나면 거부
                                |  2. 위험 점수 더하기 (기기 상태, 국가, 시각, MFA, 조회 건수)
                                |  3. 점수 50 이상 거부 / 20 이상 추가확인 / 그 외 허용
PEP <--결정-- PDP

PEP: 허용 --> 앱 | 추가확인 --> MFA 요구 | 거부 --> 차단하고 로그에 기록
```


## 최소권한 기준 (목록에 없으면 거부)
- 재무팀: SETTLE 만
- 영업팀: SALES 만
- 서비스 계정 batch-night: SETTLE, 매일 새벽 두시의 집계 작업만 


## 스코어링 결과
- 항목별 점수: MFA 20 / 기기 20 / 최소권한 20 / 세그멘테이션 0 / 위험기반인증 0 
- 총점: 60/100
- 먼저 올릴 항목과 이유: 기기, 새벽의 사건이 등록되지 않은 기기에서의 접근으로 일어났기 때문
